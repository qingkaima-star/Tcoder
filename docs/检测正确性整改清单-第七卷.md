## §103 RD-85：撞 id 那一格落成读数 ⇒「去重后口径」从免责声明变成一条能核对的账（2026-09-25 13:56）

**这一条不是新病，是卷三 §49 与 R6 §7 第 2 条留到今天的那半**。
`DuplicationScan.rankedBlocks` 先把命中按 `DuplicatedBlock.id` 去重、再截断到 20，
而 `id` 只由「出现文件集合排序拼接 + 行数」拼成 ⇒ 同一组文件上的两处**等长**克隆撞同一个 id。
撞掉的那几块**既不在榜内、也不在 `blocksDroppedByCap` 里**，于是当年三处都写着同一句话：

> ⚠️ 不做加法：不合成"总块数"（`rankedBlocks` 撞 id 削掉的块没有读数，等式天然不平）。

那句话本身没错，错的是它撑着的**后果**：一句没有数的免责声明，读者既无法反驳、也无法去核对
"到底不平多少"。R6 §7 当场写好了要修的形状（`blocksDroppedByIdCollision: Int?`，只加不改），
并留了一句「请总工裁它归哪一批」。**裁定：归本批，判据类之外的一格直传读数，不抬规则戳。**

**落了什么（四格，全部只加不改）**

1. `rankedBlocks` 返回值四元组 → 五元组，多一项 `droppedByIdCollision = input.count - 去重后条数`。
2. `DuplicationResult.blocksDroppedByIdCollision: Int = 0`。
3. 契约 `CodeMetrics.duplicatedBlocksDroppedByIdCollision: Int? = nil`（Optional ⇒ 旧报告整键缺席）。
4. 页尾那句：`outsideBoardNoteFromFields` 改由**三格逐条点名**装配，
   并且「榜外有数才开口」那道门改成**三格里任一有数就开口** ——
   否则小仓库（榜没满、榜外为 0）上这一格落了地也没有读者，等于白加。
   旧那句「另有 N 个块 / M 行未列入榜内。」**一字未动**（第 21 类盲区：加新维度时旧话术原样）。

**当年那句担心是错的**：R6 §7 说「加第五个返回值会连带动到调用点与
`DuplicationBoardCaliberTests` 的解构，而那批断言是 RD-17 的钉子」⇒ 实测**没有发生**：

## §105 RD-87：那枚"去重后总数"落进 schema ⇒ 同一个陷阱在 JSON 出口又修一遍（R6 §7 第 1 条结案）（2026-09-25 15:35）

**为什么这不算"重复劳动"**：R18 消灭的是**我们界面上**那句「共 N 处重复块」（榜内 20、榜外 96
⇒ 那句少报 96）。修法是一枚代码里的计算属性 `reportedDuplicatedBlockTotalCount` ——
**JSON 里没有这一格**。于是盘上读者（CLI `scan` 的消费者、AI、对表脚本）能拿到的仍然只有
`duplicatedBlocks.count`，也就是**榜长**。同一件事、两个出口，当年只修了一个。
申请单 `docs/R6-契约字段清单.md` §7 第 1 条点的正是这一格，且它当时就写明了形状
（Optional + `encodeIfPresent` + 唯一取法）。

**落了什么**：`CodeMetrics.duplicatedBlockTotalCountAfterDedup: Int?`（快照）。
装配那一行**只引用唯一取法、不重写加法** ⇒ R18 那把「加法只有一个家」的尺子一字未动照样绿。
名字里带 `AfterDedup`：它是**去重后口径**，不许被读成"这个仓库一共多少处克隆"——
差额那两格是 RD-85／RD-86 干的活。

**自带守卫四例（含一条纪律尺 + 它的元测试）**
- 真扫描：快照 == 唯一取法，**且严格大于榜长**（等于榜长＝落错了东西，把复印件当了总数）。
- 落盘往返 + 缺席态（没统计过榜外 ⇒ 整键缺席，不许写 `null`）。
- 纪律尺：整个 `Sources` 里这枚字段**只许出现两处**（声明 + 装配）；第三处就是有人拿复印件
  当了第二把尺子。元测试三种坏形状都要红（多出第三处／只剩声明／装配搬进冻结文件）。
