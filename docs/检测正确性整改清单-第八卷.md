## §148 「产物可机械证明来自 \<HEAD\>」这句话在"只按产物码 tree 放行"那一态里是**说过头**的（13:26 UTC）

**触发**：合完 `6a76ae1` 我在主树复跑 `verify_provenance.sh`（第 4 次落档，rc=0），
输出里**两行互相打架**——上面一行老实写着
「rev 不同（产物 `c6e67be` / 当前 `6a76ae1`）但产物码 tree 相同 `2113b4d` —— 差的只是 docs/scripts/测试，可归属」，
收尾那行却印「全部通过：产物可机械证明来自 `6a76ae1…`」。

**为什么这格要修**：两种"通过"证明的不是同一件事。
rev 相同 ⇒ 能证明那枚二进制**就是从这个提交建的**；只按产物码 tree 放行 ⇒ 只能证明它**与这个提交同一份产品码**，
而那枚二进制自己记的是别的 rev。用同一句话覆盖两态，等于给
`#62`（"认证能不能写成交付头"）递一张它买不到的收据——**报数的人会照着抄**，
抄出来的就是"T2 认证 = 交付头 `6a76ae1`"，而我们手上最多只有"同一份产品码"。

**改法**（复用已有的那一枚判定，不新增机制）：收尾句按 `PROV_BY_TREE` 分两态；
tolerance 那一态明写禁令——
「⇒ 只能报『与交付头同一份产品码』，**不许**报『认证/取证 = 交付头 …』；差的虽只是 docs/scripts，措辞不能替它合并。」

**凭据与限度（分开写，不含混）**：
· tolerance 分支**已实跑**：`.worktrees/perf-base` 里 HEAD `fdbeb52` 对 manifest `ee59c22`，
  rc=0，输出正是那两行（`/tmp/verify-prov-treebranch.log`）；
· else 分支就是**原句、一字未改**，本轮**没有** rev 与 HEAD 相等的产物可跑（下一次重打包即是），
  所以那一态本轮只做了代码核对、**没做实跑**——这句话本身也要留着，别让它被"全绿"两个字盖掉。
