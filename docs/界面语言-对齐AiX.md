# 界面语言 · 对齐 AiX（批次 P6）

> 2026-09-21 用户裁定：「设计风格按我们另一个项目 AiX 的走，统一做成他们的风格。」
> 追问后确认范围 = **全量对齐**（灰画布 + 白卡片 + azure 蓝 + 侧栏蓝色选中胶囊）。
>
> 这份文档是**改判据的依据**，不是可选项：本仓有一批守卫把旧规则（纯白无界、
> 绿色强调、内容层不许有面）钉成了机器断言，它们必须跟着这次裁定一起重写，
> 并且**逐条写下"为什么不是把阈值调绿"**。

## 2. 我们落地的取值（与 AiX 同族，但必须过我们自己那两条 WCAG 线）

参考图的 `#2B76DB` 作选中底 + 白字 = **4.48:1，差 0.02 不过 AA**。
本仓的 AA 线是硬约束（`DesignTokenTests` 逐角色钉死），所以取**同色相、可过线**的最近值：

| 令牌 | 浅色 | 深色 | 依据 |
|---|---|---|---|
| `accent.graphic`（选中底/主行动底/焦点环） | `#2A6FD3` | `#2A6FD3` | 白字压上去 **4.92:1**；白底上作图形 **4.92:1**（双线都过） |
| `accent.text`（链接/强调文字） | `#1D63C6` | `#7FB4FF` | 浅底对白 ≥4.5；深底对纯黑地面 ≥4.5 |
| `chart.blue`（数据与图表） | `#378CF7` | `#5B9CF9` | 与参考图同值，非文本 3:1 达标 |
| `Surface.ground`（画布） | `#F7F7F7` | `#0E0E10` | 深色侧**没有参考图**，按"卡片抬起"的关系自行推导并在此备案 |
| `Surface.card`（卡片） | `#FFFFFF` | `#1C1E22` | 同上 |
| `Surface.sidebar` | `#F9F9F8` | `#131315` | 比画布亮一档，靠色差不靠线 |
| `Surface.ink`（标题/数字） | `#313131` | `#F2F2F5` | 参考图实测软黑；纯黑只在深色地面用 |
| 卡片圆角 | 16pt | 16pt | 参考图量出来是"大圆角卡片"，不是 6–8pt |
| 卡片发丝边 | `#EAEAEC` 0.5pt + 投影 8%/12pt | `#2A2A2E` | 边与影**同时**存在才像参考图；单独一条线会显廉价 |

**深色侧一律标"推导值"**：参考图只有浅色态，我没有 AiX 深色截图，所以深色是
按同一层次关系（画布 < 卡片 < 抬起）推的，不是抄的。这条必须写清楚，
否则以后有人拿深色图去对 AiX 会对不上还以为是 bug。

## 3. 一个蓝：语义色必须跟着收敛

参考图里**只有一种蓝**。我们现在的 `info` 角色是 `#007AFF`（系统蓝），
`accent` 换成 azure 之后就出现**两支蓝**——这正是批次 P5 刚消灭的"两套强调色"。
处置：`info` 的图形色并入 `accent` 那一支（日志等级 `info` 与交互色同蓝，
靠**图标与位置**区分，不靠色相）。`success/warning/danger/critical` 保持不动，
所以"绿族只许一档"那条守卫继续成立（`accent` 不再是绿，反而更容易满足）。

## 4. 要重写的判据（逐条写"为什么"，不许只调数字）

| 旧判据 | 为什么现在必须改 | 改成什么 |
|---|---|---|
| 内容层不许有面（`GlassLayer.content` 什么都不画） | 新语言**要求**卡片有白面 + 发丝边；不改判据就等于每加一张卡就红一次 | 新增 `.card` 层：白面 + 16pt 圆角 + 发丝边 + 一层浅投影；`content` 层继续"什么都不画"，只服务**不带卡**的排布（读数带、行内说明） |
| 全仓只允许 `.floating` 一层投影 | 卡片的浅投影是参考图的必要成分；"只许一处"的初衷是**不许叠三层**，不是禁止一切投影 | 允许 `.card`（8%/12pt 一层）与 `.floating` 各一层；新增守卫断言**同一元素不得叠加两份阴影** |
| 强调色必须是绿（多处断言 `#15803D` / `#0D7130`） | 用户裁定换 AiX azure | 断言改成新值，并保留"必须钉死、不许跟系统强调色漂"的原意 |
| 地面必须纯白/纯黑 | 新语言是"灰画布 + 白卡" | 断言改成：画布 `#F7F7F7`、卡片 `#FFFFFF`、**卡片与画布亮度差 ≥3%**（这才是"抬起来"的可测定义） |
| 文字对比一律对 `ground` 量 | 卡片内文字的实际背景是**白卡**不是画布 | 对比度 harness 增加"背景取所在层的表面色"，卡片内按 `card` 量 |

## 5. 落地顺序（每步都要能独立复核）

1. 令牌层：`Surface` 三档 + `accent` 换蓝 + `info` 并入 + 圆角/描边/投影令牌。
2. 材质：`GlassLayer.card` + `GlassSection` 默认走 `.card`（**这一步让九页同时变卡片**）。
3. 侧栏：选中胶囊走 `accent.graphic` + 白字（多数已自动跟随）。
4. 守卫与对比度 harness 按 §4 重写；每条改动的注释里引用本文件。
5. 三态九页重拍 + 像素反查（画布/卡片亮度差、蓝的色相只有一支、投影不叠加）。

### §6.6 立一条版式规则：卡里的说明句必须挂在它解释的那一行旁边

没邻居的灰点"，而读者不会去 hover 一个看起来不像控件的东西 —— 这是**层级**缺陷，
不是重叠也不是溢出。挂载点只有两个合法形状：与它解释的那一行同排行尾（`HStack`），
或卡片头的 `trailing:`。

六处全部改完：页尾实拍先确认三处（重复与复杂度概览的条下面、热点函数表展开按钮下面、

### §6.5 报数必须给入口（守卫 G10 第一次跑就点到第二处）

进程占用排行原来是「20 行 + 一句 `NoteLine`『另有 N 个进程未列出』」：
按 CPU 核当量排序时第 2 行往后几乎全是 0.00，那 19 行不携带信息，

### §6.10 跨页边距的像素复量（`scripts/page_edges.swift`，交付态 18 张浅色图）

§6.9 那条是"文字有没有上屏"，这一条管"版面对不齐"。**跨页并排量同一个量**是本仓挖出过
四条缺陷的打法（各页单独看，差 3pt 是看不出来的）。

- 判"卡面"：三通道 ≥252（浅色画布 247 / 卡面 255）。逐行取最宽的那条白带，
  字形造成的 <30px 缝隙先并回去；报**中位数 + p10–p90**，不报众数
  （第一版报众数，结果是"1/140 行同值"——抗锯齿每行抖 1–2px，众数天然不存在）。
- 读数：九页 × 顶/尾 **18 张全部左边缘 304pt、右边缘 1255pt**。
  窗口宽 1280pt ⇒ 右边距 25pt，与规格里那条"页边距 24"对得上（差 1pt 是抗锯齿）。
  唯一的例外是「总览」页尾右边缘 767 —— 底部 `LazyVGrid(columns: pairColumns)`
  （`Views/DashboardView.swift:58`）左列的边，两列栅格本该如此，不是错位。
- **入库即带正对照**：`page_edges selfcheck` 在内存里造两张已知边距的合成画布
  （304–1255 与 272–1240，只差 32pt），量出来必须分别是那两个数。
  这一条是必须有的：上一版尺子连报三张"1/N 行同值"时，它其实**没有分辨力**，
  而"九页都一样"看起来像好消息，人最容易在这种读数上直接写"已复核"。
  造夹具也别用 `NSBitmapImageRep.setColor(atX:y:)`：对自建位图它只会刷
  `Unrecognized colorspace number -1`（实测 1.7 GB stderr）且一个像素都不画进去。
- **只覆盖浅色态**。深色九页它正确地"不出数"；换"比该行众数亮 4 阶"的相对判据试过，
  两条都坏了（浅色整行并成一条 0–1280、深色只量出侧栏 8–280），已退回并把教训写在
  `cardBands` 上面。深色一侧目前的像素判据仍然只有均亮 / 暗像素占比那一组。


### §6.11 那些分支态真的造出来了（`scripts/ax_tooltip_fixtures.sh`，覆盖率 17 → 30）

上面那句"本轮没做"已经做掉了。一套夹具把 14 个分支一个个推到界面上，
最后一趟读数：**静态 37 处 ⓘ 落点，活界面上查到 30、未命中 1、整句插值无法静态匹配 6**
（14 个批次 / 49 趟，实到 help 去重 236 条）。复跑只要两条命令：

```bash
./scripts/ax_tooltip_report.sh            # 九页 × 顶尾 + 空态 + 首启（18 趟）
./scripts/ax_tooltip_fixtures.sh          # 分支夹具 + 覆盖率对照表
```

夹具分五类，每一类都对着源码里那一条 `if`：

| 类别 | 造法 | 点亮的 ⓘ |
|---|---|---|
| 报告类 | 拿真报告删 `logs` / 删 `health` / `overall=88`（分量加权和仍 75.24）/ 追加一条历史末点 61 分 | 没有日志结果、尚未计算、分量对不上、折线只连已有点、末点与本次不一致 |
| 内容类 | 造一个有可解析 `error.log` 的小项目；一个空仓库 | 错误簇「按出现次数排序」、每千行归一、Git 分桶数据缺席 |
| 仓库拓扑类 | **在任何仓库之外**（`$TMPDIR`，跑完删）造一个装着两个仓库的目录 | 「当前只分析了提交数最多的那一个」 |
| 交互类 | `scripts/ax_press.swift` 按「暂停」 | 采样已暂停那一整句 |
| 时序类 | 首帧早拍（0.5s / 1.0s 各一次，**总览与性能监控两页都要**） | 进程表未采到、曲线等首个采样点 |

三条只有做了才会知道的事实，记下来给下一轮省事：

1. **SwiftUI 按钮的标签不在 `AXTitle` 上，在 `AXDescription` 上。** 第一次按「暂停」押空
   （229 个元素里只有 1 个有 title），差点误判成"这页没有暂停入口"。
2. **AX press 真能驱动状态**（合成鼠标做不到的一条路）：按完回读，那枚按钮的
   `desc` 从「暂停」变成「继续」—— 这既是按成功 proofs，也是"按钮是活的"这条主张的证据。
3. **多仓那条必须在仓库工作树之外造**：选中目录只要落在某个仓库里，git 会先向上定位，
   第 ③ 级"向下扫子目录"根本走不到（读数是「仓库定位偏离」那张卡）。

仍然量不到的一处：`HealthView.swift:212`「这里刻意不画一个 0 分红环…」。
它挂在 `HealthNoInputCard`（跑完了但一个维度都没算出来）上，而把报告的
`health.components` 清空之后，**启动那趟重算又会把六个维度填回来** ——
这一档要稳定夹具，得先给 App 一个"这次别重算"的入口。那是为取证改产品代码，本轮不做，
挂在 `docs/界面-乱的清单.md` §6。

**这条读数的边界要说清**：它证明句子挂上了活的可访问元素（`.help()` 落地的就是这一格，
VoiceOver 念的"帮助"也是这一格），**不**证明鼠标悬停时那个黄色气泡画得出来 ——
那一半需要真鼠标，仍然只有人工悬停拍一张才能补。
