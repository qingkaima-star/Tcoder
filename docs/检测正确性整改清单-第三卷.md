### RD-54：`SourceSkipLedger` 的样本清单交给字典遍历序 ⇒ 同一总体两次跑出两句不一样的话
- 起因不是猜的：第一次拿**真 GUI 落盘**与**真 CLI 落盘**对同一总体做逐字段对表，
  判 4 处不等，两两都是同并集不同次序：
  `命中：.gitignore ×2、.build ×1、.git ×1` vs `…、.git ×1、.build ×1`；
  `strings ×1、stringsdict ×1` 整个倒过来。
- 根因：三处 `sorted { $0.value > $1.value }` 只按计数排，全部 ×1 时次序由 `Dictionary` 遍历序决定。
  这是"同一事实两把尺子"的第三种形态：**同一事实两次渲染成两句话**。
- 修法：抽一把共用的 `SourceSkipLedger.byCountThenName`（计数降序、**并列按名字升序**），三处一起引它。
- 守卫 `testSampleListsInDisclosureSentencesAreDeterministic` 三条腿：
  ①同一批剔除项按**两种插入顺序**建桶 ⇒ 渲染串逐字节相等；
  ②独立真值是**手写**的期望串（`aaa.strings ×1、ggg.git ×1、mmm.build ×1、zzz.stringsdict ×1`）；
  ③反例钉"计数优先、并列才按名字"（`bbb ×3` 必须排在三个 ×1 之前），防它退化成纯字母序。
  sabotage：摘掉名字兜底 ⇒ 三条断言全红（含①，字典序真的会分叉）；反打 ⇒ 绿。
- 端到端复认：修后同一棵树上连跑两次 CLI，`scanLimitations` 16 条**逐字节相同**。
- 我自己在这条上又踩了两次记过的坑：`sorted(Self.f)` 少写 `by:` 标签；
  以及把 case 名写成我以为存在的 `.unlistedExtension`（真名 `unsupportedExtension`）——
  AGENTS §8 第 5 条「工单点名的符号必须读源码」再一次应验，只不过这次是我自己。
