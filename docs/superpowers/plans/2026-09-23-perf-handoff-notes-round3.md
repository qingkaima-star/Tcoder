## §AM 同一趟 A/B 顺手抓出冷启动档两处自己的洞（都归包 16 一起修）

1. **归属会盖错章**：页级 `meta.json` 的 `rev=` 写的是**跑脚本那棵树**的 HEAD（`ffcdda5`），

## §BE 包 36：`app-update` 的三口径收成一条规则，顺手封掉一条假绿通道（06:54）

**立案的原始形状（#44）**：同一份 trace 的同一个指标名，两处入口给出两个数。
下面这两条是**改动前**在同一份产物上跑出来的（`d` 指 `.scratch/tcoder-perf-03a2219-t2b-idle-run1`；
改动后两条都给 17，见 selfcheck 第 54 项）：

```
python3 scripts/trace_report.py durations $d/hitches-updates.xml --json …   # sidecar：n=28、超 8.333 ms 8 个
python3 scripts/trace_report.py summary $d                                   # 汇总表：n=17、超预算 4 个
```

| 读法 | n | 超 8.333 ms | 此前谁在用 |
|------|---|-------------|------------|
| 原始行数 | 28 | 8 | `trace_report.py` 落的 sidecar 字段 `n` |
| 按 (起始, 时长) 去重 | 17 | 4 | 汇总表 + 一致性尺 `perf_trio_agreement.py` |
| 按**值**去重 | 16 | — | sidecar 回落分支（只在 XML 读不出时走） |

**比"两个数"要紧的那格是假绿**：旧 sidecar 把 `values` 截到最小的 40 个（写侧把给人看的首屏样例
直接塞进了机器读的字段），而回落分支读的就是这个 `values` ⇒ **XML 一缺失，那把尺读到的 `max`
是"第 40 小的时长"**，而 T2 的判据量正是 `app-update` 的 `max`。
第二条方向性错误：按值去重会把**时长相等的不同事件**并成一个，于是超预算计数**只会变小**——
单向朝好看错。⇒ 本次把判据方向写死：**宁可多计，不许少计**。

**改了什么**（四个消费者、一条规则，规则现在只有一个住处 `scripts/perf_update_caliber.py`）：

1. `dedupe_pairs`：XML 优先 ⇒ sidecar 的 `pairs`（同一把键）⇒ 都没有就**不去重**、原样给行数。
   按值去重那条分支删掉。
2. `sidecar_payload`：`n` 改事件口径，行数另存 `n_rows`，加 `n_events` 与 `budget_ms`，
   `values` 不再截断，配对信息落 `pairs`。字段表与判据同住，写侧只剩一次 `write_json`。
3. `cmd_durations` 的 stdout：行数与事件数不等时补一行口径说明——首行那个 `n` 从此不会又被读成事件数。
4. 汇总表 `app-update` 那行的判定列：走回落时出声（`｜口径回落：无 (起始,时长) 配对 ⇒ n 与超预算按行数读`）。
   **旧产物不改**：它们没有 `pairs`，于是自动落在"未去重 + 标注"这一档，历史读数不需要重打。

**selfcheck 第 54 项**（`perf_selfcheck_tables.sh`）用四形状各判一次：4 行=3 事件的夹具（第 2 行是
Brown/Red 双行、第 3 行与第 1 行**同时长但起点不同**）⇒ ① `n_rows=4 / n_events=3 / n=3 / 超预算 1`；
② 走 XML 与走 sidecar 两路逐项相等；③ 只剩裸 `values` 时给 4 且必须带标注；④ 45 行的表最大值还在。
`selfcheck` 现量 **54 项 0 失败**。

subprocess 调用、判定并行。两次都是**门禁先红、我再动刀**，不是我自觉。
