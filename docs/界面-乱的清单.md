# 「乱」总清单（九页界面 · 五类）

> 这份表是目标里"先定一份「乱」的清单（重叠/溢出/对齐/层级/密度）"的那份清单。
> 它不是一次写完的：条目是**逐轮从像素里挖出来的**，每轮把新发现的补进来、
> 把修完的标状态。所以每一行都要求两样东西：**具体落点**（哪个文件/哪张图）
> 与**判据**（哪把守卫，或哪个像素读数）。没有判据的行不许写"已修"。
>
> 取证口径：深浅两态 × 顶/尾 × 九页 = 36 张，交付态那批在
> `.scratch/evidence-cfeb841/`（每页折叠线以下的滚动量、无缝成立的条件、
> 深色读数与"蓝像素为 0 的三页各有各的正当理由"，记在
> `docs/界面语言-对齐AiX.md` §6.2 / §6.4 / §6.8）。
>
> ⚠ 这份文件**不在**符号锚点棘轮 `DocReferenceRatchetTests` 的扫描面里（那把尺子
> 读的是它自己点名的 4 份文档）。所以这里的锚点是**手写时逐个核对过**的，
> 但没有机器替下一轮守着：改这份表里的符号名时，得自己确认它还在。

## 6. 已知还开着的

1. **深色一侧全部是推导值**：没有 AiX 深色参考图，深色取值是我们自己按 WCAG 线推的。
2. **hover 展开态没有像素证据**，而且这一条**测不了**（不是没测）：
   `.scratch/tools/hoverprobe.swift` 用 `CGWarpMouseCursorPosition` + 合成 `mouseMoved`
   去悬停，等 5 秒、激活 App、抖进抖出都试过，**新增窗口 0 个**；
   但**正对照同样失败** —— 把光标停在窗口自己的红色关闭键上（那个 tooltip 是系统给的，
   不可能坏），也是 0 个。⇒ 是这把尺子不灵，不是 ⓘ 出不来。
   所以"几十条搬进 tooltip 的长句还在不在"目前只有**静态**证据
   （`TooltipMigrationGuardTests` 的 A/B 两本账按 `CopyHelpBadge(` / `help:` 槽位计数），
   没有"屏幕上真的弹出来了"这一张图。要补，只能人手工悬停拍一张，
   或者给 App 加一个 dump 视图树 toolTip 的调试入口（那是为测试造产品代码，本轮不做）。
3. `skipLedger` 的行数审计默认不开，所以"按规则排除了多少**行**"仍是未知（界面只报条数）。

> 侧栏那一行的修复只有**一张**截图作证（`.scratch/sidebar-label.png`），不是 36 张：
> 引导位是侧栏底栏，九页共用同一个容器、同一份内容，页面切换不改它的布局。
> 这是"证据要覆盖那个变量"的判断，不是省事 —— 全量复拍仍然在 `79680e6` 那批里。
