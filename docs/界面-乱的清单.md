# 「乱」总清单（九页界面 · 五类）

> 这份表是目标里"先定一份「乱」的清单（重叠/溢出/对齐/层级/密度）"的那份清单。
> 它不是一次写完的：条目是**逐轮从像素里挖出来的**，每轮把新发现的补进来、
> 把修完的标状态。所以每一行都要求两样东西：**具体落点**（哪个文件/哪张图）
> 与**判据**（哪把守卫，或哪个像素读数）。没有判据的行不许写"已修"。
>
> 取证口径：深浅两态 × 顶/尾 × 九页 = 36 张，交付态那批在
> `.scratch/evidence-cfeb841/`（每页折叠线以下的滚动量、无缝成立的条件、
> 深色读数与"蓝像素为 0 的三页各有各的正当理由"，记在
> `docs/界面语言-对齐AiX.md` §6.2 / §6.4 / §6.8）。
>
> ⚠ 这份文件**不在**符号锚点棘轮 `DocReferenceRatchetTests` 的扫描面里（那把尺子
> 读的是它自己点名的 4 份文档）。所以这里的锚点是**手写时逐个核对过**的，
> 但没有机器替下一轮守着：改这份表里的符号名时，得自己确认它还在。

## 6. 已知还开着的

1. **深色一侧全部是推导值**：没有 AiX 深色参考图，深色取值是我们自己按 WCAG 线推的。
2. **hover 展开态的像素仍然没有证据**，但"句子挂没挂上活界面"这一半**已经有读数了**
   （`docs/界面语言-对齐AiX.md` §6.9 与 §6.11：14 个批次 / 49 趟，实到 help 去重 236 条；
   静态 37 处 ⓘ 落点里活界面查到 **30** 处，其余 6 处整句是插值、静态侧取不出唯一汉字串）。
   三条死路留档，别再试：
   ① `.scratch/tools/hoverprobe.swift` 用 `CGWarpMouseCursorPosition` + 合成 `mouseMoved`
   去悬停，等 5 秒、激活 App、抖进抖出都试过，**新增窗口 0 个**；而**正对照同样失败** ——
   把光标停在窗口自己的红色关闭键上（那个 tooltip 是系统给的，不可能坏）也是 0 个
   ⇒ 是这把尺子不灵，不是 ⓘ 出不来。
   ② 进程内读 `NSView.toolTip`：整棵 SwiftUI 树只翻出 1 个 NSView。
   ③ 进程内读 `accessibilityChildren`：五种装配姿势 `kids` 全 0，
   中途那条"读到了"是**同进程里别的宿主串进来的假信号**，逐字复刻后复现不出来。
   剩下真正没证据的只有那一格**像素**：黄色气泡画得出来吗？要补只能人手工悬停拍一张。
3. `skipLedger` 的行数审计默认不开，所以"按规则排除了多少**行**"仍是未知（界面只报条数）。
4. **跨页边距这把像素尺子只覆盖浅色态**：`scripts/page_edges.swift` 判"卡面"用的是
   绝对阈值（三通道 ≥252），深色九页实测"一个白卡带都不认"，于是它正确地不出数。
   试过换成"比该行众数亮 4 阶"以求两态通用 —— **两条都坏了**（浅色整行并成 0–1280 一条带，
   深色只量出 8–280 那段侧栏），已退回。所以深色一侧目前只有均亮/暗像素占比那组读数，
   边距没有像素判据；而深色取值本来就是推导值（第 1 条），没有参考图可对。


5. **一处 ⓘ 目前无法在活界面上量到**：`HealthView.swift:212`
   「这里刻意不画一个 0 分红环…」挂在 `HealthNoInputCard`（跑完了但一个维度都没算出来）上，
   而把报告里的 `health.components` 清空之后，**启动那趟重算会把六个维度填回来**
   （实测：改完的报告落盘后 `generatedAt` 与 `components` 都被刷新）。
   要稳定造这一档，得先给 App 一个"这次别重算"的入口 —— 那是为取证改产品代码，本轮不做。
   它仍有静态证据（挂载点由 `CaliberBadgePlacementGuardTests` 钉着、句子在目录里）。
> 侧栏那一行的修复只有**一张**截图作证（`.scratch/sidebar-label.png`），不是 36 张：
> 引导位是侧栏底栏，九页共用同一个容器、同一份内容，页面切换不改它的布局。
