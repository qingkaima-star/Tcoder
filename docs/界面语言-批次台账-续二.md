### §6.55 批次 P55：窄态第一次过闸门，先照出尺子自己的病，再照出一处真缺陷

§6 第 0 条（窄态四格量条不在同一条基线）挂了三个批次。三条"容易想到的路"
（换布局 / 统一留两行高 / 整带降字号）都试过算、都不成立，写在清单里。
这一批**先量再设计**：给 `ax_truncation_sweep.sh` 开一个 `SWEEP_WINDOW_WIDTH` 口子
（窄态那趟的产物另起目录、宽度打进抬头，不靠人记得"那次是窄态跑的"），
第一次拿 1080 = 本 App 自己的 `minWidth` 跑九页。

**量出来的不是"量条低一行"，是根因**：窄态四列各分约 185pt，而
`33.7 GB` + `/ 48.0 GB`、`125.4 Kbps` 这些串里**单位与数字同字号**，
是在抢本属于数字的宽度 ⇒ 值折两行 ⇒ 它下面那条量条掉一行。
P49 那三代修法治的是"单位被劈开"与"数字被截尾"，**没有治"读数带被撑高"**。

于是既没重排基座、也没留空带：值槽只放数字，单位走 `MetricTile` 现成的小一号 `unit:` 槽；
内存的分母 `/ 48.0 GB` 从值槽挪进脚注那一行 —— 分母本来就是口径，脚注那一行就是干这个的
（`ChartChrome.SeriesLegend` 的「已用 X / 总量 Y」也在第二行），分子分母仍同精度、一条读数没删。
切分走 `PerformanceSystemTiles` 里的纯函数，**故意不重算单位阶梯**
（阶梯只在 `ByteFormat` 一份，重算就是第二把尺子）。

**同一趟还照出两处别的东西**：

1. **尺子自己的病**：P54 立的逐条容忍清单里，四条时间标签的键写的是整串
   `第一次 3 天前 · 最近 3 天前` —— 键里含**测得值**。窄态一跑，仓库自己又提交了，
   数据变成「2 天前」，前缀对不上 ⇒ 两条当场掉回主门。
   **一条会因为被扫对象自己长大而失效的豁免，等于没有豁免。**
   改成只钉到数字前面那个空格（`第一次 ` / `首次 `），并把这条规矩写在清单旁边。
   脚本同时把那 2 条空转豁免**念了出来** —— "念空转而不是念成通过"要买的账，就在这儿兑现了。
2. **一处真缺陷**：总览 `ErrorClusterRow` 那条崩溃标题
   （`EXC_BAD_ACCESS (SIGSEGV) · 崩溃于 objc_opt_respon…`）格宽 557pt / 单行需 624pt，

   同一事实在两个地方两种画法。补 `.help(cluster.displayMessage)`（冻结区第二处 additive，
   AGENTS §3 已登记）。

**读数带这一格从此是被机器量掉的，不是被眼睛看掉的**：两档宽度各跑一次，

### §6.56 批次 P56：「展开其余 N …」一族改整句键——英语的单复数只能由 stringsdict 承载

英文态审计 B 类榜首就是这一族：**7 句 / 14 次**，屏上写的是
`展开其余 12 条提交`、`展开其余 35 位贡献者`。旧写法是
`"展开其余 \(n) " + noun` —— 拼完的串没有整句键（守卫 1d 那一族），
而就算把 noun 也翻了，英语 **"Show 1 more commits"** 这种语法错仍然修不掉，
因为**中文没有单复数**，机翻最容易在这里翻错。

**做法**：`DisclosureNoun` 枚举（9 个量词）× 两个态 = **18 条整句字面量键**，
复数交给 `en.lproj/Localizable.stringsdict`；`DataDisclosureButton.title` 走 `localizedCount`。
键写成 `switch` 里的字面量而不是拼串。8 个调用点改完（含依赖页那处内联的
`GlassButton("展开其余 N 项")`）；动态量词 `duplicationHiddenRowsNoun` 改返回枚举，
钉的仍是同一件事：**量词必须跟着"榜内/全量"这一态走**。

**读数**（英文态九页 18 趟，`853f717` 之前的 `d41f26c`）：
含中文片段 190→**178** 次、去重 66→**60** 句、A 0、B 36→**30**、C 30。
逐句实证：`展开其余` / `收起` / `个重复块` / `位贡献者` 在审计输出里**各 0 次**，
而屏上实读是 `Show 12 more commits`、`Show 35 more contributors`、
`Show 7 more hidden items`、`Show 12 more reported blocks`。

**新判据 `DisclosureNounCopyTests` 六条**，其中两条是这一批真正的收获：

1. **进程内把复数量出来**。英文态那几屏的样本全是复数（12 / 35 / 7），
   "只剩 1 项"那一档在真数据里从没出现 ⇒ 只量到复数就宣称"复数修好了"是**没有读数的结论**。
   这条直接在 `en.lproj` 那个 bundle 上走一遍查表 + 填数，钉住
   `Show 1 more commit` 与 `Show 12 more commits` 两种形态；
   并且**先钉"这个 bundle 不是空壳"**（连既有的「%lld 行」都查不到就当场失败），
   否则四条断言会在一个假 bundle 上取到哨兵值而全绿。
2. **反向判据差点在空集上假绿**。`stringsDictKeys` 用"行首一个 tab"认顶层键；
   我第一次用**空格**缩进写进去，plist 合法、`plutil -lint` 通过，
   而判据一条键都没看见 ⇒ "孤儿键"自然是空集、正向那条却红了。
   已按文件的 tab 约定重写，并给反向判据加了"至少看到 used.count 条这一族的键"的前置。
   **教训**：解析器认缩进不认结构时，"读不到"必须被显式当成失败，而不是让空集替它说话。

**另一条流程教训（记忆里写着、这次照犯了）**：为 58 行新开一个 Sources 文件，
全量门禁从 2 红直接变 **19 红** —— 普查分母（`SourceFileReachabilityTests` 181→182）、
视图文件归属计数（`CodeGitRestyleTests` 18→19）等**写死的分母不止一处**。
正确的修法不是把 19 个基线一起抬（那是给一次搬家付 19 处维护债），
而是**别为它新开文件**：这一族本来就属于文案词汇，搬进 `Design/LocalizedCopyKit.swift`
（137→194 行，离 400 线还远），`CodeGitDesignKit.swift` 回到 390 行，**一条基线都不用动**。

**实拍**：`evidence-853f717-p56-full/` —— 九页 × 深浅 × 顶尾 = 36 张，4/4 趟逐张判过极性。
为什么动的是按钮文案却重拍整九页：`Design/LocalizedCopyKit.swift` 在
"全九页 · 外壳与共用基座"那一行的依赖面里，**基座动一行 = 九页都要重看**，
这是这张账本本来就该有的反应。眼睛看了复杂度风险浅色尾拍：
「展开其余 12 个函数」逐字未变、榜内表格与改进建议的版式一字未动。
账表 8 行改指这一批：【实拍新鲜度】10 行 / 11 页 → 过期 0 行、【实拍格数】72 格全在 rev 全对、
【依赖面完整性】缺列 0 处。

### §6.58 批次 P58：健康评分「说明」那一列——中文字面量**自己肚子里**做插值

**量到什么**：英文态残留 166 处 / 55 句里 **B 类 27 句**，其中 9 句在 `Services/Health/**`。

```swift

```

片段与测得值在**同一个字面量里**拼完，`Text(row.component.detail)` 上屏的是拼好的那一串，

而**三条静态键守卫全是绿的**。

**这次做了什么**
1. 片段全部改整句键 + 位置参数（9 条曲线、55 条新键，含"未发现可计数的函数体"这一族
   孤句——它们原先是裸字面量，`Text(变量)` 不查表，所以登记了也白登记，必须在这里查）。
2. **分隔符与括号也是键**：`joined` 的「，」与 `noted` 的「（）」各一条键
   （`"，" = ", "`、`"%1$@（%2$@）" = "%1$@ (%2$@)"`）。片段之间能查表的只有标点，
   所以标点也该走表——挂在一处，比散在每条文案里各写一遍强。
3. 六处 `detail + "（中文）"` 改走 `HealthCurves.noted(_:_:)`，注记一律给**不带括号**的片段。
4. **预算换算法则**：`joined` 原先数"60 个字符"。中文 60 字与英文 60 字符不是同一条物理线
   （英文一个词平均 5 个字符 ⇒ 一行塞得下三四个词，后面的口径段整段舍弃）。
   改成按**显示宽度**算：全角折 2 格、拉丁折 1 格，预算 120 格 = 60 个整字，
   中文那条线一格没动，英文拿到的是同样的**宽度**而不是同样的**字数**。一条尺子，没有语言分支。

**新立的两条判据（各配元测试）**

  现在 698 条 → 残留 0 条。它与仓里两把 `containsHan` **判的不是同一件事**
