# 功能真实性清单（验收主诉第⑦条）

> 用户 2026-09-21 原话：**「所有功能都要正常使用，不能有假数据 或者假的死页面」**
>
> 这条**优先级高于观感**。它把"界面漂亮但底下是空的"从可接受的未完成，
> 改判成缺陷。本文件是这一类的唯一台账：条目**只改状态、不删除**，
> 和 `docs/界面乱点清单与修复进度.md` 同一套路子。

## 口径（什么算违反）

| 档 | 判据 | 为什么算缺陷 |
|---|---|---|
| **S1 编造数据在屏** | 界面上渲染出来的数字不是从真实项目算出来的 | 用户按监控结论做决策，假数=错决策 |
| **S2 缺证据冒充结论** | 没测到，却渲染成一个像真结论的值（0 分、"无风险"、`0`） | 本仓既有红线：缺证据必须 `--` + 中性色（见 [[评分诚实三态原则]]） |
| **S3 链路断裂** | 有写入端没有读取端（或反之）⇒ 这个功能等于不存在 | 界面暗示"我们有这个能力" |
| **S4 交互点了没反应** | 按钮/菜单/开关有 UI 无消费，或消费了但结果被丢弃 | 假页面的一种：假得最隐蔽 |
| **S5 死功** | 每 tick 计算并落存、全仓零读点 | 不骗用户，但白烧 CPU，属性能账 |

## 取证方式

三路只读走查（导航可达性 / 假数据 / 未实现与静默失败）+ 我本人逐条回源码复核。
**行号是取证时快照，可能腐烂**；判据以符号名为准（见 [[文档引用钉符号不钉行号]]）。
