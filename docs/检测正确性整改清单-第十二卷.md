## §184 开第十二卷，并把「写盘」补进 T5 的同步 I/O 词表（`.write(to:)` 此前只抓读、不抓写）

**为什么这一节属于本目标**：判据③ 的原话是「body/Mark 内**零同步 I/O**」，
而 T5 那条 `syncFileIO` 的词表里只有**读**的形状（`Data(String)(contentsOf:)`、
`contentsOfDirectory`、`attributesOfItem`、`fileExists`、`stat`、路径解析、起子进程），
**一个写盘的形状都没有**——`§182`/`§183` 未闭里都挂着这一条（`.write(to:` 那族）。
写盘和读盘在这件事上一样贵，`.atomic` 那一路还多一次 `rename`。

**先量会不会当场点红**（#65 立下的前置：补词表之前先读现量，别拿门禁当探针）：
`.write(to` 在**扫描面**（`Views/**` ＋ `Design/**`）里只有 **1 处**，位置是
`Design/LocalizedCopyKit.swift` 的 `flush()`——那是一个普通方法，既不是 `var body:` 也不是 `Chart {`，
而该文件**没有任何跨度**，所以跨度扫描对它是空集；`Services/**` 里那 4 处
（`ProjectStore` 三处报告/注册表/历史落盘 ＋ `CLIOutput` 一处重定向输出）
本来就在这条判据的作用面之外——**它管的是渲染路径，不是所有 I/O**。
⇒ 加词**零代价**：上限仍 `1/1`（那一格真债是 §72 留下的 `LogsView` 计算属性，未变），
新增形状今天不抓到人，只是把"以后写了会被抓"这句话变成真的。

**落了什么**：

1. 词表补 `.write(to…):` 一族形状（raw string 里是 `\.write\(to(?:URL)?:`），
   一条正则同时命中 `Data.write(to:options:)` 与 `String.write(to:atomically:encoding:)` 两种真形状；
2. `syncFileIO` 的**坏样例**跟着补两行（两种真形状各一行）——这条既有牙
   （`testScannerFiresOnBadSamples`）会在模式打不中时当场红，不用新造判据；
3. spec §D 里 T5 那句枚举补上「`.write(to:)` 写盘」，让"读与写都在这一条里"写在权威文档上，
   而不只写在注释里（`syncPrefs` 那段的原话就是"真实射程写在 spec 里，不靠注释撑"）；
4. **牙在同一天第二次兑现**（第一次是 §182 那两条）：我第一版用文本手术往那条正则**中间**插字符，
   把 Swift 的 raw string 收尾 `"#` 弄成了 `":,"#` ⇒ 模式末尾多吃到一个 `",`，
   **编译照过、门禁照绿**，只有 `testScannerFiresOnBadSamples` 把它打回来
   （原话还是那句「规则「syncFileIO」命中不了坏样例，它已经废了」）。
   ⇒ 两条记法：① 含 raw string 的那一行要**整行替换**，不要在中间插字符；
   ② 换完先在本地把模式从源码里抠出来、拿四个样例（两新一旧）跑一遍再进编译——
   本轮就是这么验的：四个全中，且**旧的两条不 regress**（防止把 `resolvingSymlinks` 那一族改废）。

**回执**：`--filter PerfHitch` ⇒ `Executed 22 tests, with 0 failures`，
台账行仍是 `syncFileIO 1/1`（**加词之后一处没多抓** ⇒ 与 19:09 那次现读一致：今天是零代价加面）。
**一条边界（防止把粗尺当成好尺）**：只加带 `to`/`toURL` 标签的 `.write(`，
**不**加裸 `write(`——后者会打到 `FileHandle.write(Data…)`、`Text(...)` 上的同名方法等
不属于"同步落盘"的形状，那是第 24 类「会误报的粗尺不上闸」正对着的形状：
误报会把人训练成"红了就忽略"。宁可窄一点，等真出现别的写盘形状再按同一套现读流程补。

## §185 反向探针自己也要被验：变异那一格现在过三道关（改没改进文件、输出变没变、红是不是这条判据撞的）

**为什么这一格在本目标里**：完成标准是"测得准、解释准"，而 selfcheck 里那些**反向格**（故意把尺子改坏、
要求它必须变红）是"测得准"这句话唯一的机器读者。它们此前只看一件事：**变异之后退出码非零**。
单向判据有两个空洞，本仓都记过账（第 46 类：产物为空也印「✓ 完成」；第 20 类：没读者的机制不算落地）：

1. **`sed -i ''` 在 macOS 上模式打不中就是静默落空**（不改文件、也不报错）⇒ "什么都没做"
   也可能满足"它红了"——红完全可能来自别的原因（夹具本身坏掉就算过一次）；
2. 更隐蔽的一层：**变异改进去了，但报告根本不读那一行** ⇒ 输出与变异前逐字相同，
   此时"红"与这条判据无关，把它算作牙，等于给守卫发一张空头的合格证。

**改了什么**（`perf_selfcheck_ruler_shapes.sh` 第 8 项 `selfcheck_migration`）：
变异前留一份快照 → ① `cmp` 断言**文件确实被改动**；② 抓变异前后的**完整输出逐字比**，
相同就直接报"这一格不算牙"并**不**去看退出码；③ 只有前两道过了，才有资格判红不红。
ok 那行同时把这件事印出来（**回执要能看出牙在哪**）：
「读不到守卫常量就炸（拒绝退回手抄正则）；且变异自己过「文件变了＋输出变了」两道验」。

**三格全部实测过**（不是两格＋一格推理）：

| 格 | 造法 | 尺子说什么 |
|---|---|---|
| 正格 | 原样跑（真把 `coarsePattern` 改名） | 两行 ✓，`oks=2 fails=0` |
| 变异落空 | 把 sed 的搜索串改成一个不存在的名字 | ✗「变异没改进文件（sed 静默落空）——这一格从「有牙」退化成「什么都没做」」 |
| 惰性变异 | 往夹具里加一个**报告不读**的常量，只改它 | ✗「变异之后输出与变异前逐字相同 ⇒ 那句「读不到守卫常量」根本没发生」 |

后两格都在 `/tmp` 的脚本副本上造（`mig_harness.sh` 把这一项单独 source 出来跑），
**没有动交付物**，也**没有**把"验不到"写成"已验"。

**顺手一条规模账**：`perf_selfcheck_ruler_shapes.sh` 现在 **393/400** ⇒ 下一次再往这个文件加臂之前先拆
（同一族第 6 次逼近；#105 记的是锚点尺宿主，这条记在这里，别等门禁当天才发现）。
