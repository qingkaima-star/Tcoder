## §217 #123：判据① 的 p95 判定落到批次产物里——稀缺的真人窗口不能只剩一次 stdout 的尾巴

## §218 #62：认证只能绑在冻结的产品码上——这条不该靠人记，写成一张调度约定（并把已有的机器读者点清）

## §220 #127：收尾人手复核「没做成」被读成「做成且没人动」——未判这一格第一次落盘，并由唯一那把资格尺读回

**形状**（不是推理，是 09-27 实测复现）：`post_window_quiescence` 在静默探针取不到时只印一行
「（收尾静默探针取不到，污染判定不做）」就 `return 0`，**meta 一个字段都不落**；而唯一的资格判据
`period_eligibility` 的形状是「没有污染标记就算合格」。于是尺子掉下来的那一趟**必然放行**：

```
===== period=interaction：跑收尾复核（探针取不到）=====
    （收尾静默探针取不到，污染判定不做）
  meta 里的收尾相关字段： （一个都没有）
  period_eligibility → eligible=True | 有资格答 T1（交互期 hitch = 0）
===== period=idle：同上 =====
  period_eligibility → eligible=True | 只答心跳期；**不许**拿去交 T1
```

两句都是绿灯，而**同一句还被 `perf_trio_agreement` 读进 §1.3 的 3/3 计数**（一把判据、两个读者，
所以这一处修完 ① 与 ② 一起受益）。危害不是假想：判据① 唯一的取证出口是一次稀缺的真人窗口
（AGENTS §2.2 禁一切点击/滚动自动化），那一趟若正好撞上尺子掉，就会**在没有一次人手证据的情况下
把「交互期 hitch=0」交出去**。而「探针时好时坏地报 -1.00」是记过账的真实故障形状——
它编译到 `$SCRATCH` 下的哈希名，别的会话在同名位置放个目录就编译失败（`perf_probes.sh` 头注 ①②）。

**先量危害半径，再动判据**（避免把历史读数顺手改口）：盘上 245 批里 63 批没有 `quiescence_after_seconds`，
但**其中 0 批是「已完成导表却被放行」的**——今天 cert13／cert14probe／cert15／cert16 那几批缺这一格，
是因为它们带着 `REFUSED`（录制开始前就被闸门拒掉，压根没走到收尾复核）。
⇒ 这是一条**潜伏的、单向朝好看错**的通道，不是一次已经发生的错账。这句话必须这样写，不许写成"已避免了几批"。

**修法（写侧落格、读侧负责拒，只加字段不加闸门）**：
1. `post_window_quiescence`：取不到 ⇒ `meta_write ... quiescence_recheck=unavailable`（并照旧 `return 0`、
   样本照旧留盘——拒发生在**引用那一刻**，不在录制中途灭失一趟）；做成 ⇒ `quiescence_recheck=measured`。
   正对照那一格不是装饰：没有它，「没写成 unavailable」与「这段代码根本没跑」在下游长得一模一样。
2. `perf_eligibility.human_recheck_refusal`：显式 `unavailable` ⇒ 两档都拒，拒因写「没做成／既没证有人在动
   也没证没人动」。单独一枚函数而不是往 `period_eligibility` 里塞——那枚函数已经 47 行，再长就撞
   「函数 ≤ 50 行」那把门（本仓口径：拆一格一个函数才是修复，抬线不算）。
3. **裁定：缺这一格的老批次不追溯**。`period_eligibility` 只认显式 `unavailable`。

## §221 ① 的存量清点：盘上 15 批交互样本无一能交判据①，三条理由叠在一起

**为什么要做这一次清点**（不是再发现一个缺陷，是**在要那 30 秒之前先把「能不能用旧数交」判死**）：
判据① 要求「交互期 hitch 帧 = 0 且 p95 帧间隔 ≤8.4 ms」，而 AGENTS §2.2 之后唯一的取证出口是需求方一次真人滚动。
在开口要之前必须先答一句：**盘上那 15 批 `period=interaction` 的样本能不能顶掉这一笔？** 逐批过完，答案是**不能**，三条理由各独立成立：

1. **产物码全是旧的**（`886fa059b56e`／`a57db970a0e1`／`26ae8c5c63d0`／`feb7cdbf820a` 四棵），
   没有一棵等于当前的 `8bc57fc72716` ⇒ 按 §218 第 3 条「换码即失效，不许静默继承」，
   它们连"引用"的资格都没有，只能当历史形状。
2. **输入是 `synth@8ms`**（CGEvent 投递），报表自己就标着「非真人手感」；
   节奏 125 Hz 不低于帧预算 ⇒ **能答 p95 那一半、答不了手感那一半**（`input_rate_qualification` 就是这么分的）。
   而 `INPUT=synth` 在 09-23 那条令之内，不能为了凑数再投一次。
3. **判 T1 要的逐帧表在旧批次里缺**：`每帧 GPU 用时(ms)` 那行打的是「未覆盖（这份 trace 里没有这张表）⇒ 不判」。
   尺子自己那一句就是「判 T1 用上面三张逐帧表 + 呈现侧 p95」⇒ 这些批次连判据的**输入**都不齐
   （#117 那一族的另一个形状：一趟可以"落定"，但判据要的那张表不在）。

**顺带把两句话写准，免得下一轮被引用歪**：
- **hitch 计数不能读成卡顿率**：这批样本的 `hitches.xml` 计数从 3 到 376 个都有，
  而 §AC 已经证过「同一份内容三趟报过 14 / 22 / 364 行，变的只是流水线延迟档位」。
  ⇒ 「非零」在旧批次上**不是**"这套代码卡"的证据；能交的只有 p95 与逐帧表。（同批实测的内部矛盾也记着：
  a5298d5-run3 印 `364 次 = 18.20 /s 严重超(>=1/s)`，同表 HTR 却印 `5.00 ms/s 无感`——两个读者对同一份数据的话不是一句话，
  这正是"计数那一维不许单独定达标"写进表头的原因。）
- **p95 的"差一点点"要带仪器分歧**：15 批里 4 批名义预算不过，超出量是 **0.015 / 0.029 / 0.062 / 0.063 / 0.088 ms**，
  全部小于两台仪器的分歧（0.66 ms）⇒ 只能说"这批在名义档与实测档之间不收敛"，不能说"差 0.02 ms 所以没达标"。

**这把要来的窗口削到什么程度**（这一条是本节的实际收益）：真人窗口一跑，链路已经三段都验过——

## §223 #129：§7.3 与 §7.5 两纸可比条件只有写点没有读者——并池那一侧第一次被问「这几趟是一种条件吗」

**这一条与前两条同族、方向不同**：#127／#128 是"**一趟之内**的读数没落盘或落盘没人读"，
这一条是"**落了盘、跨趟没人比**"。`build_flavor`（release／debug）与 `coexisting_instances`（共存实例数）
一直老老实实写进每一批 meta（盘上现量 **239 批 release＋239 批 coexist=1**，8 批老批次缺格），
但 `grep` 全仓**没有任何一处读过这两格**——于是同一池里混进 debug 产物或多实例那趟时，
一致性尺照样报「一致／不一致」，而真相是"这几趟根本不该放在一起比"。
两纸规矩的原文就在代码边上：`perf_probes.sh` 的 `TARGET_FLAVOR` 注释写着
「spec §7.3 要求两档的**绝对值永不混比**」，`require_idle_target` 的 ATTACH_PID 那一段写着
「meta.json 里已记 coexist=$n」——**话说了、格记了、闸没有**。

**做法（判据本体一枚新模块，接入现成的混档出口）**：
`perf_comparability.py` 里 `comparability_of(meta)` 把两格读进读数、
`comparability_precheck(got)` 复用 `_precheck` 那个"混档一律不判"的出口（退出码同一档 2＝**这把尺没有对象**，
不是"量出来不一致"，两者不许混成一个红灯）：某一趟自己写着「未知」⇒ 按它自己的标签就不可比；
观测到不同 ⇒ 点名是哪一维、引 §7.3／§7.5 的出处。
**缺格不追溯**（与前两条同一张裁定）：空值不参与判定，只有**不同**或**未知**才不判。
`comparability_of` 单独成一枚是为了让**键名只出现一次**，常驻臂可以直接喂 meta 字典验它——
改名或漏读当场红，而不必为测一条映射去造一整套能过 `summary_load` 的表夹具。

**常驻臂＝selfcheck 第 73 项（90→91 项，0 失败）**：六格 `0|2|2|2|0|Y`
（同条件放行＝**防恒拒**／混口径拒／混共存实例拒／未知拒／老批次缺格放行／键名映射对）
＋两行话术钉（拒因必须分别引用 §7.3 与 §7.5，"拒了却没人知道被哪条规矩拒"是同族老账）。
**破坏验证**：把 `comparability_precheck` 改成恒不拒 ⇒ 臂红在六格那行（拿到 `0|0|0|0|0|Y`——三个 2 全变 0，正是「混口径／多实例／未知又被并进同一池」的形状）；复原 ⇒ 绿。
