## §202 五处夹具的"`mktemp -d` 失败就退回 `/tmp/固定名`"收进本轮 outdir——但要说清：**危害我这回没复现到**，这是一次一致性收敛，不是抓到一条在跑的缺陷

**为什么动它**：#111 那次普查的清单里有一行「75／71／68-70 的夹具 `mktemp -d` 失败时回落到**固定 /tmp 名**，

⇒ 动它首先是**向仓库自己的惯例收敛**（顺手满足 AGENTS §1.6「一次性产物不进 `$TMPDIR`」）。

（同族教训：#111 的第一次实验因干扰物寿命太短而拿到假阴性——**实验不成立就不能拿它当证据**，

## §204 去认证 T4 的路上抓到一条**假绿**：`ready_ms = 0.0` 被判定式读成「p50 = 0 ms ⇒ T4 达标」——"没量到"与"0 毫秒就绪"必须分开（#114）

**怎么撞上的（这条不是审计来的，是**动手量**撞来的）**：机器难得空载（`load1` 2.7），
按 #109 的前置重新打了一份含 #108 修法的产物（rev `197f01e`、`clean=true`、
盘上实算 sha 与 manifest **逐字相等**），预热两启、域 7 条键，然后跑 `switch` 档。
读数：**`ready_ms: 0.0`**、`window_seen: 未探测到实例`、整表跨度 695 ms。
我那支认证棒（`.scratch/t4ab/run_t4.sh`）的判定式是 `if v is not None` ——
**它会把 0.0 当成一个可用读数**，五趟里只要三趟给 0.0，就会印出
「**p50 = 0 ms，T4 达标（按 #109 写死的线）**」。这条线是我前天为了"不许因为测不到就改判据"写下的，
结果它自己有个洞：**0 恰好是"最容易达标"的值**。

**根因（一句话）**：`launch_ready_ms` 取"最早的尾巴段起点"当就绪点，
而**整表只有一段、且那段从录制第 0 ms 就开始**时，这个起点就是 0
⇒ 与"秒开"在数值上**不可区分**。这种表的真实含义是**启动过程根本没进表**
（xctrace 起的那个实例探不到／起得太快就退了）。函数原来只在"空表"时才返回 None。

**修法（一条判据，不加阈值、不挑好看的数）**：就绪点必须**晚于**表里最早那段的起点，
否则返回 None —— "没看见"就是"没看见"。判据本体
`launch_ready_ms` 是**唯一来源**（`perf_switch.sh` 的 `first_frame_ms` 也读它，
且 `None → 未观测到` 早就写好了）⇒ 表格列、JSON、话术三处一起变，不会只闭合一个出口（#71 那族的教训）。

**双向验收**（都在真数据上，不是"应该没问题"）：
```
五向 selfcheck 第 19 项（拆出五个形状各钉一次）：
  a 真产物形状（一堆小段＋一段长尾巴）→ 837.4   b 无尾巴 → 620.0   c 空表 → None
  d 含一条远处的零时长段 → 200.0            e 整段从录制起点开始 → None   ← 新那一向
  ✓ launch_ready_ms 五向都对 …            ◇ selfcheck：79 项通过，0 项失败
真产物（今晚那份 0.0 的 xml）重跑报表：
  启动到就绪：未解出（…或整段从录制起点就开始 ⇒ 启动过程根本没进表；两种都按未覆盖处理…）
```
⚠ 顺带抓到一处**假覆盖**：第 19 项此前算了 `d` 却**只印不判**（没有任何断言用它的值）
⇒ 那一格一直是零覆盖；本轮不但补了断言，还换了夹具
