| `CrashReportParser`：`if name.contains("crash") \|\| name.contains("diag") { return true }`；`LogDiscovery`：`.ips` / `haystack.contains("diagnosticreports")` / `name.contains("crash")` 一律归 `.crash` | **文件名就能进崩溃通道** |
| `ScoreCurvesTeamRuntime`：`crashPenalty = min(48.0, Double(crashCount) * 12)` | 一条合成崩溃 = **扣 12 分**，扣光封顶 48 |

需要的四态（不是布尔）：`疑似报告 / 读取失败 / 解析失败 / 确认崩溃`；
只有 **确认崩溃**（有真实事件证据）才许增加 `crashCount`，其余三态各自计数并带**原因与文件位置**。
另外三格：事件时间（`eventDate: Date?`，与 `fileMtime` 分开）、无时间戳事件计数、
应用身份（bundle id / 构建版本 / 采集环境）—— **历史报告与当前观察窗口分开展示**。

### 6.3 覆盖率链（RD-25~26）—— 总工本人读到的现场

`CoverageAnalyzer`：`Array(reports.sorted { $0.linesTotal > $1.linesTotal }.prefix(6))`
—— **正是用户说的"按分母大小只保留前六份再累加"**。
需要的身份维度：`format`（lcov / json 摘要 / JaCoCo / istanbul）、`runKey`（同一次测试运行）、
`moduleKey`、`sourceFingerprint`（提交或源码指纹，mtime 不算证据）、
`consideredCount / includedCount / droppedByCap`（上限必须披露，不许静默截断）、
`mergeConfident: Bool?`（不可靠合并就**分开呈现**，不给伪精确总覆盖率）。

### 6.4 函数识别链（RD-01~09）

识别结果要能带出：**边界是否可信**、**该形状是否属已支持**、**降级模式名**（轻量正则 vs 结构解析）。
正则降级时，`scanLimitations` 必须写明"哪些语言/形状未覆盖"，界面读得出"部分测量"。
外层与内部回调的复杂度**口径要落在数据上**（独立 / 含嵌套累计二选一），不许只有注释里写着。
