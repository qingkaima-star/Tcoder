## 0. 这份表回答什么问题

产品里有**两类**上屏的长句，此前只有一类被看着：

| 类 | 落在哪 | 谁来读 |
|---|---|---|
| 收进 ⓘ 的长口径 | `kAXHelpAttribute` | `scripts/ax_dump.swift` + `ax_tooltip_coverage.py`（AiX 轮建的，已把 help 的 A 类从 16 清到 0） |
| **直接铺在页面上的正文** | `AXValue` / `AXTitle` / `AXDescription` | **此前没有任何仪器** |

正文这一类正是改进清单 **F13** 说的：`Services/` 拼好整句、经 `Text(变量)` 上屏，
静态双语守卫按"UI 入口前缀"认文案，看不见 `base = "…"`；help 读数器只读 help，也看不见它。
F13 当时只能给一个 python 粗筛数（32 文件 / 327 处），**因为没仪器才只能粗筛**。
本轮把仪器补上：`scripts/ax_body_text.swift`（读数）+ `scripts/ax_body_audit.py`（台账）。

## 1. 仪器先自证：两把尺子必须能互相对上

同一个实例、同一趟，`ax_dump` 与本仪器各读一次（`健康评分` 顶与尾）：

```
help 仪器  SUMMARY windows=1 visited=163 withHelp=41
body 仪器  SUMMARY windows=1 visited=163 withText=113 withHelp=41
```

`visited` 与 `withHelp` 逐项相等 ⇒ 走的是同一棵树、对 help 的读法没有偏；
而 `withText=113` 是 help 那把**看不见**的量。深度上限同为 60，这是刻意对齐的。

英文态是否真的换了语言，用同口径对照（不是"看起来像"）：

| 批次 | 含中文片段 | 去重句数 |
|---|---|---|
| 中文态 9 页（`AX_SET=zh`） | 1479 次 | 410 句 |
| 英文态 9 页（`AX_LANG=en`） | 220 次 | **81 句** |
| 空态·中文 9 页（`AX_EMPTY_REGISTRY=1 AX_SET=empty-zh`，头 `2b5b1f0`） | 432 次 | 22 句（A 20 / B 0 / C 2） |
| 空态·英文 9 页（同上 + `AX_LANG=en`） | **0 次** | **0 句** |

**最后那一格是"查了、答案是零"，不是"没查"**：两批空态各 18 个读数文件、
`TEXT` 行各 **504** 条、`HELP` 行各 **252** 条（逐批 `grep -c` 数出来的），
驱动脚本自己也对每一趟断言了"TEXT 行数 > 0"（18 趟全过，退出码 0）。
所以英文态首启界面**一条中文正文都不剩** —— 与有项目那一档（81 句）正好对照：
漏网的全是"算出来的句子"，不是"框架上的句子"。
空态那批 A 类 20 句是同一批文案在中文态下的样子（键在、查表也查得到，中文态本来就该显示中文），
**不构成债** —— 再一次说明 A 类判据只在英文态有意义。

⚠ 中文态那批的 A 类是 240 句，**不能与英文态比**：中文态下查表返回的就是中文键本身，
A 类判据只在英文态有意义。这条写死在这里，免得下一个人拿 240 去和 12 比。
