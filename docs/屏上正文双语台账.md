## 0. 这份表回答什么问题

产品里有**两类**上屏的长句，此前只有一类被看着：

| 类 | 落在哪 | 谁来读 |
|---|---|---|
| 收进 ⓘ 的长口径 | `kAXHelpAttribute` | `scripts/ax_dump.swift` + `ax_tooltip_coverage.py`（AiX 轮建的，已把 help 的 A 类从 16 清到 0） |
| **直接铺在页面上的正文** | `AXValue` / `AXTitle` / `AXDescription` | **此前没有任何仪器** |

正文这一类正是改进清单 **F13** 说的：`Services/` 拼好整句、经 `Text(变量)` 上屏，
静态双语守卫按"UI 入口前缀"认文案，看不见 `base = "…"`；help 读数器只读 help，也看不见它。
F13 当时只能给一个 python 粗筛数（32 文件 / 327 处），**因为没仪器才只能粗筛**。
本轮把仪器补上：`scripts/ax_body_text.swift`（读数）+ `scripts/ax_body_audit.py`（台账）。

## 1. 仪器先自证：两把尺子必须能互相对上

同一个实例、同一趟，`ax_dump` 与本仪器各读一次（`健康评分` 顶与尾）：

```
help 仪器  SUMMARY windows=1 visited=163 withHelp=41
body 仪器  SUMMARY windows=1 visited=163 withText=113 withHelp=41
```

`visited` 与 `withHelp` 逐项相等 ⇒ 走的是同一棵树、对 help 的读法没有偏；
而 `withText=113` 是 help 那把**看不见**的量。深度上限同为 60，这是刻意对齐的。

英文态是否真的换了语言，用同口径对照（不是"看起来像"）：

| 批次 | 含中文片段 | 去重句数 |
|---|---|---|
| 中文态 9 页（`AX_SET=zh`） | 1479 次 | 410 句 |
| 英文态 9 页（`AX_LANG=en`） | 220 次 | **81 句** |
| 空态·中文 9 页（`AX_EMPTY_REGISTRY=1`） | 432 次 | 22 句（A 20 / B 0 / C 2） |
| 空态·英文 9 页（同上 + `AX_LANG=en`） | **0 次** | **0 句** |

空态这两批**在两个头上各跑过一次、逐格相同**：第一次 `2b5b1f0`（`AX_SET=empty-{zh,en}`），
第二次出货头 `53f9b1c`（`AX_SET=e2-{zh,en}`，`provenance ✅ revision == HEAD`）——
中间隔着 P22/P23 两笔动过空态与趋势卡的代码提交，所以这一格**必须重跑**而不是引用旧数。

**最后那一格是"查了、答案是零"，不是"没查"**：两批空态各 18 个读数文件、
`TEXT` 行各 **504** 条、`HELP` 行各 **252** 条（逐批 `grep -c` 数出来的），

所以英文态首启界面**一条中文正文都不剩** —— 与有项目那一档（81 句）正好对照：
漏网的全是"算出来的句子"，不是"框架上的句子"。

**不构成债** —— 再一次说明 A 类判据只在英文态有意义。

⚠ 中文态那批的 A 类是 240 句，**不能与英文态比**：中文态下查表返回的就是中文键本身，
A 类判据只在英文态有意义。这条写死在这里，免得下一个人拿 240 去和 12 比。

### 7.2 P69 之后剩的 3 句 B 类，逐条为什么不在文案批里修

写这一节的目的是**拦住下一个人"顺手补个键"**：这三条里有两条一补键就会造出更贵的缺陷。

1. `共 N 天 · 单日峰值 M 条`（`Views/Logs/LogsTrendCard.swift` 的 `subtitle`）
   —— **一句里两个可数名词**（天 / 条），英语两个槽各自要选 `one`/`other`
   （`1 day · peak 1 entry` vs `2 days · peak 5 entries`）。
   现有出口 `localizedCount` 只收一个 `Int`，`localizedFormat` 只收 `String`
   （收 `String` 是故意的：把 `Int` 传给 `%@` 会当场段错误）。
   **正解是先把多槽入口的形状定下来**（含"两个槽都补千分位、且不许误伤译文自带数字"），
   而不是把复数降级成单数键 —— 后者看起来能变绿，实际是把英语写坏。
2. `EXC_BAD_ACCESS: (SIGSEGV) · 崩溃于 <符号>` 两句（静态 grep 不到，运行时拼的；
   产出点在 `CrashTextParsing` 的 `title(haystack:symbol:procName:)`）
   —— 这句的结果被存进 **`ErrorCluster.displayMessage`，而 `ErrorCluster` 是 `Codable` 落盘字段**。
   在产出处翻译 = **把界面语言烘进持久化数据**：中文态跑的一次分析，之后切英文也永远读回中文；
   而 `CrashEvidenceClassification` 在 `crashSignature(from:)` 取不到签名时
   **拿这条 message 兜底当 `signature`**，`signature` 又正是聚类的 `id` ——
   换语言重扫可能让同一个崩溃重新成一条簇。
   **这一条要先动数据模型**（把"哪几段是人话、哪几段是机器 token"分开存），
   不是登记一条键的事。谁想快修，先回答"落盘字段该不该带界面语言"。

**本轮另立的一条规矩**：句末标点也随语言。若干整句用 ` · ` 组装时句号只能在末尾补一次
（`LogSummary.crashEvidenceFootnote` 就是这个形状），写死 `。` 会让英文句子尾巴挂一个
U+3002 —— 而这把尺子按**码点**判"还残留中文"，键化做完了那一行照样算红。
出口是 `Design/LocalizedCopyKit.swift` 的 `endingSentence(_:chinese:)`。
