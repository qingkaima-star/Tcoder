### §6.30 一次"门禁红了"的归因：真值必须和被测数据同快照（不是放宽容差）

`1171 / 0 失败` 之后 12 分钟，同一批代码重跑门禁红了 3 条，全在自扫描那一路：
`totalCommits` 报 **985** 而 `git rev-list --count HEAD` 读到 **1059**、
`commitsAnalyzed` 680 vs 735、作者集中度 0.7794 vs 0.7959。

**先证机制再动手**（三个候选，两个被证据排除）：
① 分析器窗口上限？排除——`ShellGitAnalyzer.maxCommits = 20_000`，1059 远没到；
② 报告是缓存的旧文件？排除——`selfScan()` 是**现扫**，只是进程内缓存一次；
③ **取数时刻不同**：成立。`reflog` 里 `766e497 → 985` 证明"985"是那次运行期间
   真实存在过的 HEAD；随后 `merge ws/perf-base` 一次带进 74 个提交（现在 1059）。
   也就是说：**扫描在 t0 取了快照，断言在 t1 才现取真值，而 t0→t1 之间别的流往共享主树合了一笔。**
   同一份代码在树安静时重跑 → 1171/0。

**修法不是把 5 个点容差放宽**（那是把尺子锯短），而是让真值**进同一份快照**：
快照结构体 `SelfScan` 里新增的那一格 git 真值，在 `make()` 中紧贴 git 分析取一次
（`all` / `nonMerge` / `merges` / `topShare`），六条断言一律改读它。
顺带把 `revListCount` / `independentTopAuthorShare` 改成 static 并由快照复用
——**不复制第二份 Process 实现**，也不留无调用方的死代码。
`git` 取数从此全仓只有测试基座 `SelfScanHarness` 的那个静态取数出口一处（实例方法 `runGit` 只是它的转发）。

**这条对验收口径的意义**：「全量门禁 0 失败」这句话**必须连着"在哪棵树上、树静不静"一起读**。
主树是共享集成树，跑一轮 test 要 3~5 分钟，期间任何一次 merge 都会让"现取真值"类断言漂红。
以后我报门禁数字，会同时给 `git log -1` 与"跑完再量一次 rev-list 是否等于跑时读数"。

### §6.35 批次 P34：截断扫描报了 17 条，逐条判下来真缺陷是 0 条——问题在尺子

最典型的一条：复杂度风险页尾「榜内只列 20 个… 另有 91 个块 / 629 行未列入榜内。
另有 253 处拷贝因指纹预算未展开。」实宽 586、单行需 639、实高 13pt，

还带 `.fixedSize(horizontal: false, vertical: true)`，所以它**折成两行**；
只是 AX 把整段文字挂在第一行那个元素上，交回来的高就是一行。

**我差点把这条当缺陷立案**，而且是立案给一条正在写的流（`CodeViewSupport.swift` 三小时前
由 WS-R7 Advice 动过）。拦下来的是那句老判据：**报出一堆债之前，先证明扫法理解被扫对象的约定**。
这里的"约定"就是——这个组件允不允许折行。

所以这一笔改的是**尺子**，不是界面：把这一类误判写进脚本头注，并给出分诊规则
（`DataFootnote` / `DataCaption` / `NoteLine` / `GlassSection` 的 subtitle 会折行 ≈ 噪声；
`DataTable.tableCell` 定宽格与侧栏项目名写死 `.lineLimit(1)`，报出来才是缺陷）。
**没有**去造一个"从 AX 判断能否折行"的通道——那个通道不存在，硬造就是猜，
而猜出来的判据会把人逼去绕路改代码。

顺带一条自己的账：写这类插文档/脚本的 python heredoc 时，
**内容里出现 ASCII 双引号会直接截断字符串**——这一趟我连撞三次，
第三次是因为留下了一行"其实用不上的中间变量"，里面正好带 ASCII 引号。
规矩要收紧成：**这类脚本块里一个 ASCII 双引号都不许出现**，中文引用一律「」。

### §6.37 批次 P36：P18 修对了一半——水平切字修了，垂直方向被顺手改成居中

36 张在 `fb94e88` 上重拍之后逐页过眼睛，错误日志页尾那张「错误趋势」裁到原始像素看清了：
警告数那条 0 值橙色虚线**横穿过日期数字**（`9/21` 被划过去）。

根因在 `ChartAxisEdge.anchor`，也就是**我自己 P18 写的那一处**：

```
guard … else { return .center }                 // y = 0.5
if position >= 1 - edge { return .trailing }    // y = 0.5
if position <= edge { return .leading }         // y = 0.5
```

`UnitPoint.leading` / `.center` / `.trailing` 的 **`y` 分量都是 0.5**，
语义是"拿标签的垂直中点对齐刻度线"。x 轴刻度线就在绘图区底边，
于是半个标签掉进绘图区，贴着 `y=0` 画的线正好穿过它。

### §6.40 批次 P39：一条"死锚点"差点被我改成散文绕过去

### §6.49 批次 P49：窄态（1080）首拍——一个缺陷修了三代，顺手查出逐页账自己漏了一格

**为什么去看窄态**：本 App 的 `minWidth` 是 1080，用户可以把窗口拖到那儿；
而取证口径从头到尾只在 1280 那一档量过。`capture_pages_isolated.sh` 本来就吃
`CAPTURE_WINDOW_WIDTH`，只是配对驱动没透传 —— 补上透传并把 `width=` 写进 PROVENANCE 之后，
窄态第一次进了可复跑的取证口径。

**首拍就抓到一条**（乱清单 §2 新增行）：性能页系统资源那行，磁盘折成「201 MB/」+「s」，
内存把「GB」整块挤到第二行。修了三代才对：

| 代 | 做法 | 结果（都是重拍才知道的） |
|---|---|---|
| 一 | `lineLimit(1)` + 缩放到 0.8 | 折行没了，但内存显示成「30.0…」、网络「228.2 Kb…」——**数字截尾比折行更坏** |
| 二 | 留两行 + 纵向 `fixedSize` | 截尾没了，但「201 MB/s」仍断成「201 MB/」+「s」——断点在斜杠后，是 Unicode 换行规则给 `/` 的合法机会，**我上一版的假设（只会断在空格）是错的** |
| 三 | 在每个 `/` 前插 U+2060 WORD JOINER（只改渲染，数据/日志/目录键一字不动） | 「936 KB/s」单行、「163.4」/「Kbps」在空格处断 ✔ 全分辨率确认 |

**还开着的一条**（记在乱清单 §6）：窄态下两行读数会让四格的量条不在同一条基线上
（内存那格的条比 CPU 低一行）。彻底的解法是把这条读数带在窄态折成 2×2
（`ViewThatFits` 先试一行四枚、放不下再退两列），而不是继续调字号。
本轮不顺手做：它要重排 `ReadoutStrip` 与 `DataBandSeparator` 的关系，属于基座改动。

**自查表查出一格漏列**：逐页账的基座行原来只列了外壳三件，
没列 `Design/**` —— 而这一批改的正是 `Design/SharedComponents.swift`。
**改了读数基座而表一句都不会红**。守卫只读表，它查不出表少列了什么；
这格是人对着表读出来的。已把 `Design` 整目录并进基座行的依赖面，
并把基座行改指当前头重跑的**整批 36 张**（`evidence-8327ba3-p49-wide-full/`，四趟全过极性）。

窄态也留了一整批（`evidence-8327ba3-p49-narrow-fixed/`，36 张四趟全过），
但**窄态新鲜度没有进逐页账** —— 表只量默认宽度那一档，这句话说在白纸上比藏在读数里好。
读数：表 10 行 / 实际查 72 格 / 过期 0。
